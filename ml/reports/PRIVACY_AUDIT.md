# Privacy audit

The approved NYC query selects only a small set of public operational fields and omits names, street addresses, phone numbers, emails and complaint narratives. Raw data is under ignored `ml/data/raw/`; processed and evaluation data are also ignored. No production database, NagrikOS user records or synthetic demo cases were accessed. No collected case content was uploaded to an external model service.

Preprocessing normalizes Unicode and whitespace, redacts recognizable emails, Indian and US phone numbers, selected national identifiers, and street-number address patterns from the chosen text field. It withholds location by default and uses source-scoped hashed IDs for lineage. Validation checks processed rows for these same obvious patterns. All 1,000 prepared rows are marked `privacy_review_required=true`; this is an explicit warning that automated patterns cannot reliably find personal names, indirect identifiers, Hindi addresses or uncommon number formats. The script flags some name cues but does not claim to remove every name.

The local raw file should be available only to authorized researchers. Do not commit, publish, email, or send raw/processed text to an LLM. Human review of the 15 case IDs in the ignored annotation sample is still outstanding. If a source contains citizen narrative text, a full privacy review must happen before sharing or training, including lawful use, retention, linkage risk and manual review of redaction misses. Conditional Indian datasets have not passed that gate.

## Phase 2 handling

The Nandi source is publisher-labeled synthetic. Its acquisition script retains only generated ID, text, category, domain, urgency and language in the ignored raw subset; it excludes persona, channel, writer and other metadata. Prepared rows pass the same pattern redaction and carry `data_kind=synthetic`, `category_source=synthetic_generated`, `urgency_source=synthetic_generated`, and `privacy_review_required=true`. The source is still pending human review for accidental person-like strings, memorized content or indirect identifiers; a synthetic provenance claim is not a privacy guarantee. Its raw, processed, split and 15-ID review artifacts stay in ignored `ml/data/`. No Mendeley, OpenCity, BBMP or Kaggle case content was collected, and no collected text was sent to an external model service.

## Track A Phase 3 real-source handling

The official OpenCity/Janaagraha CSV was verified by publisher MD5 and local SHA-256. It contained address, location, coordinate and ward columns. The full CSV was deleted after a 1,000-row field-minimized, redacted extract passed checksum and row-count checks. Only hashed local IDs, redacted title/description and original category/subcategory, agency, creation date and status remain in the minimized file. The separate processed file retains description as candidate narrative, original source labels, null app department/urgency, and `privacy_status=pending_human_review`. Both text files are Git-ignored and have inherited Windows ACLs removed; access is explicit for the owner, local sandbox account, SYSTEM and administrators.

Automated screening flagged 30 address patterns, 19 phone patterns, 1 email, 2 handles, 31 possible names and 265 indirect-location cues among selected rows; multiple flags may occur on one row. A 30-ID local stratified queue covers 29 source categories, all three splits and 11 flagged cases, without publishing text. The automated validator found no remaining *recognized* direct-identifier patterns, but unknown names, private circumstances and uncommon addresses can remain. **No human privacy review has been completed**, so the usable real-text count is 0. See [retention and reviewer protocol](PHASE3_PRIVACY_PROTOCOL.md).

## Track A Phase 4 privacy update

The Phase 3 queue counts above are historical. The [Phase 4 rights and privacy audit](PRIVACY_RIGHTS_PHASE4.md) found residual URL, long-number and PIN-like patterns in the first redacted extract. A second local pass redacted them and refreshed checksums without touching NYC or Nandi. A repeat aggregate scan found zero matches in ten listed direct-identifier patterns in both retained OpenCity text files. This does not rule out indirect identification or establish consent. The refreshed 30-ID queue covers 25 source categories, all three splits and every observed flag type; 13 IDs carry privacy flags. **All 1,000 remain pending human review.**
