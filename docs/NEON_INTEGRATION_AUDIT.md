The Git-ignored `backend/.env` supplies testing URLs to Ubuntu WSL. This audit did not print them. A read-only WSL connection confirmed the testing endpoint had zero public tables before migration. Earlier [`NEON_POSTGRESQL.md`](NEON_POSTGRESQL.md) records a local SQLite snapshot, not a Neon import. The separate S3-compatible object-storage adapter adds **no relational schema change**: `attachments.filename` is already a random primary key and is also the private object key; `uploaded_by` and `complaint_id` remain ownership metadata. The relational copy does **not** transfer attachment bytes.

The pool pre-ping and connection timeout bound some transient failures. Application writes are not automatically replayed after an uncertain PostgreSQL commit, because a blind retry could duplicate a complaint; this behavior still needs live branch testing and an explicit idempotency design if required.

The owner authorized and the [offline target guard](../backend/scripts/check_testing_target.py) confirmed the testing URL host matched the supplied branch mapping; `alembic upgrade head` and `alembic current` succeeded. No Neon snapshot existed or was created, and the initial revision has no destructive downgrade. Create a recoverable testing-branch point before further writes. PostgreSQL CRUD, authentication, role isolation and storage round trips remain to be tested with synthetic data; preserve the original SQLite database and local attachment files.
