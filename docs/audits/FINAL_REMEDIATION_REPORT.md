## Transactional email design gate

Current signup, password-reset and staff-invitation flows call Mailjet before committing their database transaction. An accepted message may therefore contain a link that later rolls back. The existing `mail_outbox` table has only ID, recipient, subject, body and creation time; it has no delivery state or worker. A partial change that only moves the send before or after commit would exchange one inconsistency for another.

A durable design needs an encrypted notification payload so tokenized links are not stored as plaintext; a unique event key; pending, leased, accepted, permanent-failure and uncertain states; attempt count and capped backoff; lease expiry; sanitized failure category; and provider message ID. Insert an event atomically with account state, then let a worker claim rows with `FOR UPDATE SKIP LOCKED`. Retry only failures known to be unaccepted. Timeouts and crashes after a send attempt enter **uncertain** and require Mailjet activity or manual reconciliation, never automatic resend. Deploy a reviewed schema migration and encryption key with the worker disabled, then producer code, validate on staging, and only then enable delivery. Exactly-once provider delivery cannot be guaranteed.

This outbox is **not implemented or migrated** in this pass. It remains P2 for a public release. No live Mailjet message was sent.

## Release controls and residual risks

- GitHub `main` currently has no branch protection or ruleset. The `neon-admin` and `neon-schema` environments retain reviewer rules, and repository workflow tokens default to read-only. The new CI workflow does not itself make checks required before a direct push.
- `render.yaml` says automatic deployment is off, but the real Render integration deployed the authorized push. The effective service setting and rollback process need an operator review before relying on a manual release gate.
- `neon-admin` currently lists only the `DATABASE_URL` secret name. The protected demo-credential cleanup workflow requires `DIRECT_URL` too and will fail closed; it was not dispatched.
- Neon production branch protection and Render's installed Python dependency inventory were not independently verified.
- The existing production administrator account was previously created, but hosted interactive sign-in, MFA, role isolation, signup/recovery, private attachment writes and end-to-end delivery remain unverified in this pass.
- Render Free availability/cold starts and Mailjet deliverability beyond the earlier one-message test remain operational risks for a public site.

**Current decision:** both fix batches are published, and a private read-only showcase of the tested UI is **GO**. A public launch remains **NO-GO** until hosted authentication/MFA, storage, current dependency inventory and release controls are verified, and the Mailjet transaction risk is resolved or explicitly accepted. Future production changes require their own integration gates.
